- **Purpose**: Reflect the SECOND validated round from the co-deck workspace (ADR-0002 amendments rounds 4–6) into native QuickDL features: ① original-audio forcing against YouTube auto-dubbing (`--audio-lang auto|<code>`; real failures: an English seminar delivered with Japanese dub audio, a Korean news clip with Korean-dubbed audio), ② caption language configuration (`--captions-langs "ko,en"` — both languages fetched per video, gap-fill not first-found), ③ translated-caption acquisition with an honest fallback chain (manual → auto → YouTube auto-translated → `failed`, each sidecar tagged `manual|auto|translated|failed|unknown` in `subtitles[]`), ④ documented (not implemented) external-translation fallback keyed off the manifest because YouTube's translation endpoint rate-limits (429) — mirrors co-deck round 6.
- **Verification performed**:
  - Full suite: `.venv/bin/python -m pytest tests/` — **85 passed, 1 warning** (60 pre-existing + 25 new; the warning is the pre-existing `test_app.py` background-thread teardown race).
  - `bash scripts/audit.sh`: all checks pass except the pre-existing environmental `CONSTITUTION.md not found` finding (unchanged from the prior round).
  - i18n parity: 16/16 locales at 75 keys (`test_all_locales_have_same_keys` green); baseline 72 → 75.
  - CLI smoke: `--help` renders the two new flags localized in en and ko.
- **Decisions**:
  - Anti-dubbing is the DEFAULT (`--audio-lang auto`): the probe resolves the original spoken track (`audio_is_original` → `language_preference` → video `language`) and the format selector's first alternative gains `bestaudio[language^=<code>]` with the untouched fallback chain; the merged MP4 gets `-metadata:s:a:0 language=<code>` (plain-list `postprocessor_args`, applied at the ffmpeg merge). Service-layer behavior stays byte-identical when `audio_lang=None` (`test_default_opts_unchanged` unchanged).
  - Caption plan is computed from the probe's `subtitles`/`automatic_captions` keys; `failed` languages are NOT requested (no doomed fetch) but recorded honestly with `path: null`. When a probe exposes no caption data at all, the legacy pattern string passes through byte-for-byte (`source: unknown`).
  - yt-dlp sidecar filenames cannot distinguish manual vs auto for the same requested code — the plan-time source is recorded and the limitation documented in the spec (§3.1).
- **Issues / open items**: Web-UI wiring of the new flags remains future work (spec §2 non-goal). The `--captions-langs`-driven external translation step (co-deck round 6 full chain) is documented for consumers, not implemented here. `audit.sh` CONSTITUTION.md finding still requires a repo-level decision.
